# План команды: до 5 часов на хакатон

Основа уже готова. Ниже оставшаяся работа в порядке приоритета. Точное оставшееся время считать по дедлайну организаторов; последний час сохранять на проверку и репетицию.

## P0 — обязательно до защиты

| Задача | Исполнитель | Оценка | Готово, когда |
| --- | --- | --- | --- |
| Прочитать README кита и сверить схему/правила | Backend + AI | 15–20 мин | Ясно, являются ли skills текущим снимком, как задан следующий грейд, что значит max_level, разрешены ли повторы и облачная обработка |
| Реализовать импорт оригинальных employees.json, events.json, skills.json, activity_history.csv | Backend | 45–60 мин | Загружены 200 профилей, 40 событий, 60 навыков, вся история; UI принимает дополнительные профили/CSV без ручной переделки файлов |
| Сверить расчёт прогресса с китом | Backend | 15–25 мин | Нет повторного начисления истории; правильно работают gain/max_level и идентификатор прохождения |
| Настроить основной AI-провайдер и проверить живой запрос | AI | 15–20 мин | На карточке режим AI; выбранные IDs валидны; нет выдуманных событий; ключ только в .env |
| Проверить качество на контрастных профилях | AI | 35–45 мин | Изменение требований/истории влияет на выбор; самый низкий навык не выбирается автоматически; минимум 3 фактора, желательно все 4 |
| Проверить и доработать объяснения | AI + Frontend | 20–30 мин | Видны реальные разрывы и влияние истории; числа подтверждаются данными; при необходимости добавлено сравнение альтернатив |
| Проверить HR-view на полном наборе | Frontend + Backend | 20–30 мин | Видны частые дефициты, отсутствие шага и участие; неизвестные значения не смешаны с нулём |
| Проверить запуск одной командой на втором компьютере / Docker | Ответственный за релиз | 20–30 мин | Человек без помощи автора запускает README-команду и проходит демо |
| Проверить безопасность режима показа | Backend | 10–15 мин | Локальное демо на синтетике; если нужен доступ по сети — предварительно сделан парольный вход, удалён публичный выбор HR |
| Финальный прогон и репетиция | Все | 30–45 мин | Пройдены тесты, сборка, импорт новых данных, сохранение прогресса, отказы API; демо длится 2–3 минуты |

Задачи выполняются параллельно, но разработчики не должны одновременно менять один и тот же файл.

## Распределение для трёх участников

- A: `schemas.py`, `ingest.py`, `db.py`, правила прогресса и их тесты.
- B: `web/src/`, интерфейс импорта оригинальных файлов, HR, сообщения ошибок.
- C: `ai/providers.py`, оценка качества, ключи в локальном окружении, README, сборка и демо.
- Изменения маршрутов `main.py` координирует A; B и C заранее согласуют контракты.

Для двоих: A объединяет backend/AI, B — frontend/QA/README. Второй провайдер и дополнительное оформление откладываются.

## Контрольные точки

1. Ближайшие 20 минут: у всех запускается основа; разобраны форматы кита.
2. Следующий час: импорт оригинальных данных и хотя бы один живой AI-вызов.
3. Следующий час: качество рекомендаций, объяснения, HR и сценарий с новым профилем.
4. Далее: исправления, проверка задержек и воспроизводимости.
5. Последние 45–60 минут: заморозка новых функций, локальный резерв, видео и репетиция.

## P1 — только если P0 готов

- Живая проверка NVIDIA и переключение провайдера; сейчас адаптер есть, но работает только ручной выбор конфигурацией.
- Учёт input/output tokens и расходов; квоты запросов уже есть.
- Переводы RU/KZ и проверка терминов носителем языка.
- Короткий блок «почему другой вариант отложен».
- Разбивка HR «нет шага»: нет кандидатов / ещё не рассчитано / AI недоступен.

## После хакатона

Полноценная авторизация/SSO, PostgreSQL, Alembic, нормализация справочников, история изменений схемы, промышленный аудит и резервные копии. Валюта, награды и интеграции — только после подтверждения ценности рекомендаций.

## Чек-лист защиты

- [ ] Чистый запуск одной командой.
- [ ] Полный оригинальный датасет импортируется.
- [ ] Дополнительный профиль + история загружаются в оригинальном формате.
- [ ] Живая AI-рекомендация укладывается в 10 секунд.
- [ ] Интерфейс отвечает до 2 секунд на измеренном наборе.
- [ ] Объяснение опирается минимум на 3 фактора.
- [ ] Выполнение изменяет правильные навыки по gain/max_level.
- [ ] Повторное нажатие не удваивает прирост.
- [ ] Прогресс сохраняется после обновления страницы.
- [ ] Сотруднику недоступны чужие профили и HR-экран.
- [ ] На HR-экране есть три обязательных среза.
- [ ] Резервный алгоритм и кэш не выдаются за свежий AI-ответ.
- [ ] Кит и секреты не попали в Git.
- [ ] Подготовлены локальная сборка и короткая видеозапись живого AI.
