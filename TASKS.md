# Задачи интеграции Career Quest

Текущая интеграционная ветка: `work/career-quest-integration`. Исходные ветки: `feature/career-quest-mvp`, `work/backend-kit-ai`, `work/frontend-ux`. Указанные пользователем SHA являются контрольными точками, а подтверждённые источники и итоговый commit фиксируются в отчёте интеграции.

Актуальные инструкции: [README.md](README.md), [docs/INTEGRATION.md](docs/INTEGRATION.md), [docs/DEMO.md](docs/DEMO.md). Исходные задания [BACKEND_TASK.md](BACKEND_TASK.md) / [FRONTEND_TASK.md](FRONTEND_TASK.md) и оба handoff сохранены для контекста, а не как перечень текущих ограничений.

## Обязательный результат

- Профиль и траектория используют backend как источник истины: навыки, история, следующий грейд, critical и highest_grade.
- 1–3 рекомендации учитывают требования грейда, разрывы и историю участия; mandatory исключены.
- Выполнение соблюдает gain/max_level/5 и occurrence_id. Повтор одной сессии не начисляет прогресс, ответ backend обновляет профиль.
- HR показывает дефициты, отсутствие шага с причиной и участие без двойного подсчёта missed/no_show.
- Оригинальный kit-v1 и дополнительные профили/история загружаются через HR: dry-run → результат → подтверждение. Demo-v1 остаётся совместимым отдельным форматом.
- Режимы ai/rules/fallback/no_candidates и cached различимы. Отсутствие ключа не мешает локальной демонстрации.
- Сотрудник не видит чужие профили/HR; HR не выполняет активности за сотрудника. Cookie, Origin и X-Requested-With сохранены.
- Запуск воспроизводим одной командой, kit/секреты/локальная БД не публикуются.

## Финальная проверка перед публикацией

1. Запустить backend pytest и pip check, frontend npm test и production build, git diff --check. Подключить полный локальный kit через CAREER_QUEST_KIT_DIR, не копируя его в fixtures.
2. Пройти совместный сценарий на отдельной SQLite по INTEGRATION.md. Отдельно фиксировать реальный HTTP, браузер, Docker и live AI: имитация не подтверждает эти проверки.
3. Зафиксировать результаты и оставшиеся ограничения в INTEGRATION.md, сохранив оба handoff.
4. Проверить директорию, remote, ветку, status и точный состав файлов. Не включать BACKEND_TASK.md или другие чужие изменения без проверки их происхождения; не использовать слепое git add .
5. Включить только согласованные файлы в интеграционный commit. Перед push ещё раз проверить `git remote -v`, `git branch --show-current`, `git status`. Не сливать main/master и не создавать финальный PR автоматически.

## За рамками текущей интеграции

Корпоративный SSO, полная казахская локализация, PostgreSQL/миграции, денежная статистика AI и автоматический failover провайдеров. Они не заменяют проверку основного пользовательского сценария. Личные достижения необязательны; публичные рейтинги и баллы за обязательные процессы не добавляются.
