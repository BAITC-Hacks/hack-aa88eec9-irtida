# Решения для пятичасового хакатона

1. Модульный монолит: React + FastAPI + SQLAlchemy/SQLite. Один контейнер обслуживает UI и API.
2. База создаётся через create_all. Миграции Alembic отложены до стабилизации реальной схемы кита.
3. Каталог небольшой: справочники хранятся в одном валидируемом JSON, без векторной БД и RAG.
4. LLM выбирает IDs среди допустимых событий. Все числовые объяснения и прирост считаются сервером.
5. Алгоритм rules — прозрачный baseline: benefit × max(0.35, 1 - 0.15 × пропуски формата) + 0.1 × min(успешные участия формата, 3). Это наше предположение для демонстрации, не правило организаторов. История не является основанием оценивать личные качества.
6. Дефициты рассматриваются только относительно требований следующего уровня. Нет правила грейда — система сообщает об отсутствии данных.
7. Одно событие сейчас считается однократным. При наличии повторных сессий в ките нужно добавить occurrence_id, сохранив идемпотентность именно прохождения.
8. Профили — текущий снимок навыков, история — контекст. Подтвердить по README кита.
9. Импорт append-only: одинаковые записи пропускаются, конфликтующие отклоняются. Правила обновления existing profiles нужно уточнить для формата жюри.
10. Демо-вход локальный, без паролей, с реальным серверным разделением прав после входа. Для публикации нужен полноценный auth; переключатель роли нельзя оставлять публичным.
11. OpenAI и NVIDIA подключаются одинаковым контрактом. Невалидный JSON/ID или тайм-аут дают явно обозначенный rules fallback.
12. Автоматических реальных API-вызовов при запуске нет. Тесты не расходуют credits.
