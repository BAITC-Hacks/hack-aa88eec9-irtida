# Демонстрация: 2–3 минуты

1. **0:00–0:15 — проблема.** Сотрудник видит активности, но не понимает, как они связаны с ростом.
2. **0:15–0:35 — профиль.** Middle Backend Engineer, требования Senior, разрывы навыков.
3. **0:35–1:05 — рекомендация.** Вызвать AI. Показать, почему важен System Design с учётом требований и истории. Не выдавать режим rules за AI.
4. **1:05–1:25 — результат.** Выполнить активность. System Design растёт по правилу каталога; незакрытый разрыв остаётся видимым.
5. **1:25–1:50 — HR.** Дефициты, отсутствие подходящего шага, участие по событиям.
6. **1:50–2:20 — новые данные.** Импортировать дополнительный профиль и историю, получить рекомендацию. Для защиты нужен адаптер оригинального кита: demo-v1 сейчас только для разработки.
7. **2:20–2:40 — ценность.** Прозрачный следующий шаг для сотрудника и понятные потребности в обучении для HR.

## До выступления

- Проверить запас времени и лимиты API.
- Заранее собрать локальный контейнер/приложение и сохранить отдельную демонстрационную БД.
- Подготовить синтетический профиль с конфликтующими сигналами и записать короткое видео живого AI.
- Прогнать сценарий один раз полностью, затем использовать чистую отдельную БД.

## При сбое

- API: явно показать режим подбора по правилам или ранее сохранённый результат.
- Интернет/хостинг: локальное приложение и SQLite, всё оформление хранится локально.
- Для демонстрации именно AI использовать заранее записанный ролик, обозначив, что это запись.
