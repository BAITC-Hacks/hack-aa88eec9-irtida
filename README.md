# Career Quest

База веб-приложения для HackAlem AI: профиль → объяснимый следующий шаг → выполнение → прогресс → HR-срез.

**Статус: работающая основа на собственных синтетических данных, не завершённое решение ТЗ.**
Главные оставшиеся задачи: [TASKS.md](TASKS.md).

## Быстрый запуск

С установленным Docker Compose из корня проекта:

```sh
docker compose up --build
```

Открыть **http://127.0.0.1:8000**. При первом старте создаются SQLite и демонстрационные данные.
Ключи API не нужны: выбран честно обозначенный алгоритмический режим `rules`.
Первичная сборка требует интернета. Перед защитой заранее собрать образ и проверить запуск без сети.
Docker-конфигурация подготовлена; в среде подготовки Docker отсутствовал, поэтому контейнерный запуск ещё нужно проверить.

### Без Docker

Нужны Python 3.11+ и Node.js 22+ (рекомендуется актуальная LTS).

```sh
python run.py
```

Windows PowerShell, если окружение уже создано:

```powershell
.\run.ps1
```

Если Python не в PATH: `.\run.ps1 -PythonExe 'C:\path\to\python.exe'`.
Скрипт создаёт `.venv`, устанавливает недостающие зависимости, собирает frontend и запускает сервер на loopback.
Остановка: Ctrl+C. Если порт 8000 уже занят работающим Career Quest, используйте открытую страницу или остановите предыдущий процесс.

### Разработка в двух терминалах

```sh
python -m venv .venv
# Windows: .venv\Scripts\activate
# Linux/macOS: source .venv/bin/activate
python -m pip install -r server/requirements-dev.txt
python -m uvicorn app.main:app --app-dir server --reload --host 127.0.0.1 --port 8000
```

```sh
cd web
npm ci
npm run dev
```

Frontend разработки: http://127.0.0.1:5173. Vite проксирует `/api` в FastAPI.
Документация API: http://127.0.0.1:8000/docs.
Изменяющие запросы требуют заголовок `X-Requested-With: CareerQuest`; это относится и к ручным вызовам из Swagger/curl.

## Что уже работает

- Три экрана: демонстрационный вход, профиль/траектория, HR-обзор.
- Сессия в HttpOnly cookie; backend проверяет роль и принадлежность профиля.
- Разрывы по навыкам и покрытие требований следующего грейда.
- Рекомендации по нескольким факторам с четырьмя проверяемыми основаниями.
- Серверные адаптеры OpenAI и NVIDIA; выбор через настройки.
- При отсутствии ключа, тайм-ауте или невалидном ответе — явная отметка резервного алгоритма.
- Транзакционное выполнение активности; повторный и конкурентный запрос не начисляет прогресс дважды.
- Кэш рекомендаций зависит от профиля, истории, каталога, модели и версии prompt.
- HR: дефициты навыков, отсутствие доступного шага, завершения/пропуски/отказы.
- Валидация и атомарный импорт внутреннего JSON-формата `demo-v1`; повторный импорт без дублей.
- Автоматические проверки критических правил и API.

## Демо-сценарий

1. Войти как **Сотрудник 01**.
2. Нажать **Подобрать шаги**. Вверху будет System Design, хотя самый низкий навык — Public Speaking.
3. Раскрыть основания: текущий грейд, разрыв, требования следующего уровня, история.
4. Отметить практикум по архитектуре выполненным: System Design 2 → 3; покрытие требований 55% → 64%.
5. Перезагрузить страницу — прогресс сохраняется.
6. Выйти, войти как **HR-специалист**, открыть агрегаты.
7. В HR загрузить `examples/additional-profile.json`, затем открыть профиль E004.

Данные в `examples/` придуманы для разработки. Это **не стартовый кит организаторов**.
Для чистой репетиции можно задать новый путь `DATABASE_URL=sqlite:///./data/rehearsal.db` перед запуском: исходная база останется нетронутой.

## Подключение AI

Скопировать `.env.example` в `.env`; добавить ключ **только в backend-настройки**.

```dotenv
AI_PROVIDER=openai
OPENAI_API_KEY=<ваш ключ>
OPENAI_MODEL=gpt-4.1-mini
```

Или:

```dotenv
AI_PROVIDER=nvidia
NVIDIA_API_KEY=<ваш ключ>
NVIDIA_MODEL=meta/llama-3.3-70b-instruct
```

Перезапустить приложение; при Docker выполнить `docker compose up -d` после изменения `.env`.
Не добавлять префикс `VITE_` к ключам. Не отправлять ключи в чат или репозиторий.

Backend передаёт модели один профиль без имени, требования и допустимые активности с историческими агрегатами.
Модель выбирает 1–3 IDs. Схема и принадлежность каталогу проверяются; числовые объяснения строятся сервером из исходных фактов.
OpenAI использует строгий JSON Schema и `store=false`. Это не гарантия Zero Data Retention.
NVIDIA использует совместимый Chat Completions endpoint и серверную проверку JSON.
Автоматического переключения между двумя облачными провайдерами пока нет; при ошибке включается `rules`.

Живые обращения к платным API не выполнялись: ключи не предоставлены. Адаптеры проверены на имитированных ответах, качество и задержку нужно проверить на реальном API.

Ограничения по умолчанию: 7 секунд на API-вызов, 200 выходных токенов, 6 вызовов/минуту на профиль, 300 вызовов за скользящие 24 часа на приложение.
Кэш не расходует квоту. Квоты — ограничение запросов, не точный денежный бюджет; учёт токенов/расходов остаётся задачей.

## Импорт и правила данных

Схема `demo-v1` описана в `server/app/schemas.py`, примеры — в `examples/`.
Импорт принимает общий JSON: `employees`, `skills`, `events`, `grade_rules`, `history`.
`POST /api/v1/imports?dry_run=true` проверяет без записи. Обычный запрос сохраняет одну транзакцию.
Неизвестные ссылки и конфликты существующих записей отклоняются; существующие профили не перезаписываются.
Навыки импортированного профиля считаются текущим снимком: история не начисляет их повторно.

**Критически важно:** четыре отдельных файла и CSV из официального кита пока не поддерживаются. После получения README нужно добавить адаптер, сохранив внешний формат организаторов. Не предлагать жюри переделывать файлы под `demo-v1`.

Прирост: `max(0, min(gain, max_level - current, 5 - current))`.
Покрытие: `sum(min(current, required)) / sum(required)`. Это показатель навыков, не обещание повышения.
Неизвестный навык не считается нулевым. Если нет требований следующего грейда, система сообщает об этом.
В текущей основе одно событие завершается один раз на сотрудника; повторные прохождения нужно согласовать со схемой кита.

## Архитектура и структура

React → REST → FastAPI → SQLite. AI — модуль внутри backend, не отдельный сервис.

```text
web/src/                 интерфейс, типы, API-клиент, CSS
server/app/main.py       маршруты, сессии, контроль доступа
server/app/domain/       расчёт прогресса и допустимых шагов
server/app/ai/           адаптеры LLM и prompt
server/app/ingest.py     внутренний импорт; точка подключения кита
server/app/schemas.py    входные контракты Pydantic
server/app/db.py         модели SQLAlchemy
server/tests/            pytest: бизнес-правила и API
examples/                собственные синтетические примеры
docs/                    сценарий демо и решения
data/private/            только локальные данные; исключены из Git
```

Для пятичасового хакатона справочники объединены в JSON-каталог; профили, история, рекомендации, сессии и квоты — отдельные таблицы.
Используется `create_all` для новой БД. Alembic и миграции изменений схемы ещё не добавлены.
При масштабировании понадобятся PostgreSQL, миграции, нормализация каталога и общий rate limiter.

## Границы безопасности

- DEMO_MODE позволяет выбирать любой синтетический аккаунт, включая HR. Это специально упрощённый **локальный** вход, не production-authentication.
- Сервер и Compose по умолчанию доступны только на 127.0.0.1. Не открывать этот режим в интернет или корпоративную сеть.
- При `DEMO_MODE=false` демо-вход отключён; полноценную авторизацию ещё нужно подключить.
- Сервер защищает собственные/HR-маршруты, проверяет Origin и специальный заголовок для изменения данных.
- При HTTPS включить `COOKIE_SECURE=true`; разрешённые Origin задаются явно.
- `.env`, база, логи, `node_modules`, виртуальное окружение, build и `data/private` исключены из Git.
- Не использовать реальные персональные данные. Условия передачи кита в облачную LLM сверить с организаторами.
- Геймификация, рейтинги, валюта и прогноз оттока в основу не входят.

Основная рабочая ветка проекта на GitHub: `feature/career-quest-mvp`. Секреты и локальные данные в неё не добавляются.
